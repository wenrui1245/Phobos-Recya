# AI 建筑产线分离回归

本补丁以 `095f42950824d743f1d770021f57e55ca5a6e949` 为基线，完善现有主建筑、防御建筑两条产线，不新增 INI 开关。

## 行为

- 主产线继续处理普通建筑及挂接升级；独立产线处理非挂接的 `BuildCat=Combat` 基地节点。
- 防御工厂调用原版 `DemandProduction` 后通过 `Unsuspend(false)` 启动。通过原版 `FindFactory(true, true, true, house)` 找可用建造厂；暂停生产或建造厂不可用时保留进度，建造厂全部消失、玩家接管或所属方战败时取消。
- 完成后在确定性的模拟更新中调用原版放置处理，不向本地输入队列写入 AI 指令。保留原提交的 30 帧重试间隔和八次失败后放弃该坐标的规则。
- 放置返回成功后标记对应节点并清理任务；原版放置中可能删除工厂，通过现有 Detach 注册监听失效，返回后不再解引用旧指针。
- 取消防御生产保留原版退款和对象清理，跳过对主产线生产类型和主产线建造厂的清空。已有其他防御工厂时不覆盖它。
- 保存防御工厂指针、节点位置、重试时间、次数及放弃列表，读档通过现有 Swizzle 恢复指针。需要使用同一版 DLL 新建存档；不兼容旧版存档布局。

## 已核实的原版接口

- `0x42EB50`：主产线节点挑选。共同使用已建检查、全局旗标、Placed、`IsValidBaseNode` 和重新规划的坐标，防御产线不再遗漏后两项语义。
- `0x45038F–0x4503C5`：原版工厂创建后调用 DemandProduction，再调用 Unsuspend。
- `0x4FB0E0`：原版 Place 事件处理函数。使用 YRpp 已有参数契约；其声明丢弃了返回值，本补丁局部适配为 bool。`0x4FB512` 从结果标志返回 AL，`0x4FB5BA` 返回 false，两处均清理 16 字节参数。
- `0x4CA0A1`：复用已有取消生产钩子。自有防御工厂跳至 `0x4CA0E3`，保留此前退款及此后产品释放，跳过原版 `0x4CA0DA` 对主建筑产槽的清空。
- `0x4F7371`：复用现有 House 析构入口，在 ExtMap.Remove 前清理。不能在扩展析构函数中清理：容器可能已先解除所属方的扩展指针，取消生产钩子便无法识别防御产线。整体场景清理由游戏处理原生工厂。

未新增钩子或扩大覆盖区间。共享入口维持原有调用顺序；原版及其他引擎的完整组合仍需游戏实测。

## 自动回归

在具备 Python 3 和 VS C++ x86 工具链的环境中运行：

```powershell
./integration/ai-building-production/run.ps1 -Python python
```

测试提取实际生产控制器、取消生产分派和六个连续存档字段，只替换原版调用边界。覆盖启动与进度、成功时工厂被删除或保留、失败重试、断电恢复、取消、失效指针、所有权变化、已有其他工厂、升级与分类资格、原版重建坐标及完整存档任务恢复。输出和中间产物保留在已忽略的 `.private/ai-building-production`。

这属于宿主模拟回归，不能替代 Ares/Phobos 联机和原生存读档实测。

## 游戏验收

新开 AI 对局，确认主建筑与防御建筑同时施工，且主建筑持续推进。分别在防御施工、就绪但被挡住两种状态下用本版保存再读取；观察不重新扣费、不换到错误格、不出现重复建筑。再覆盖断电恢复、最后一座建造厂出售或打包、建造厂更换、堵塞八次、建筑摧毁后重建。最后以两台电脑联机验证同步，不能用单机结果代替。
